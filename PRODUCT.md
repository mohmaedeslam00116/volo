# Product

## Register

product

## Users

Arabic-speaking developers who delegate coding work to an AI agent every day, inside their projects on Windows-first desktop. Their context: mid-task, switching between editor, terminal, and review. The primary job on any screen: start a session, read what the agent did, approve or deny the next action, and keep moving. Arabic is the default language; code stays left-to-right.

## Product Purpose

Volo is an Arabic-first desktop shell over the Cline agent harness: chat, file diffs, terminal execution with explicit approval, and session history, with the user bringing their own model key and zero server cost to the maintainer. It exists because no polished coding-agent desktop speaks Arabic or treats approval as law. Success looks like: a developer runs a full agent task in Arabic, trusts every execution because each one asked first, and shows the 20-second demo GIF to a friend.

## Brand Personality

Bold, precise, composed. Three words: **confident, exact, calm**. The voice of a senior engineer narrating their own work: short sentences, exact numbers, no hype. Emotionally: control without anxiety. The interface should feel like Antigravity's ambition with Linear's restraint.

## Anti-references

- Light-mode SaaS marketing pages and generic AI-tool landing clichés.
- Glassmorphism panels, gradient text, and decorative blur used as style.
- Hero-metric blocks (giant number, small label) anywhere in the product.
- Identical icon-plus-heading card grids repeated down a page.
- Tiny uppercase tracked eyebrow labels above every section.
- Numbered 01/02/03 scaffolding that decorates instead of sequencing.

## Design Principles

1. **The agent asks; Volo enforces.** Every execution passes a visible approval gate. Trust is a rendered state, not a promise.
2. **Arabic first, code untouched.** The shell reads right-to-left; code, terminals, and diffs always stay left-to-right.
3. **Show the work, not the theater.** Sessions, diffs, costs, and statuses are inspectable facts. No marketing inside the tool.
4. **Density with discipline.** Developers live here; information density is welcome, but one component vocabulary everywhere.
5. **Zero-cost honesty.** No accounts, no phone-home, no hidden metering. What the app claims about privacy must be true in the code.

## Accessibility & Inclusion

WCAG 2.2 AA as the floor: body text contrast ≥4.5:1, full keyboard operation of chat/approvals/navigation, visible focus states, and `prefers-reduced-motion` alternatives for every animation. Full RTL layout with bidi-safe message rendering (mixed Arabic/code must never break reading order).
